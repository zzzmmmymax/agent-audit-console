# v0.2.0 release audit

Audit scope: Stage 8 MCP/Agent Integration, Stage 9 Web Audit Experience, and Stage 10 Policy Simulation & Risk Explainability. Base feature commit: `dfa695c45c0156bd1297b1fb66addf49d4119613`.

## Findings

| ID | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| V2-001 | Blocker | No release candidate branch or final v0.2 documentation existed. | Created `release/v0.2.0`; release notes, upgrade guidance, changelog, and reports added. |
| V2-002 | High | CI used official actions backed by the deprecated Node 20 runtime. | Updated to official Node 24-backed `checkout@v5`, `setup-go@v6`, and `setup-node@v5`; RC/master CI are the compatibility gate. |
| V2-003 | Medium | README still labeled v0.2 features as v0.1/development and linked the old release. | Updated version, quick start, setup, policy, compatibility, and limitations text. |
| V2-004 | Medium | Release upgrade evidence needed a real v0.1 artifact/data directory, including a snapshot. | Official v0.1.0 Windows artifact created a run, event chain, diff, and pre-change snapshot; RC opened schema 3, listed/showed/verified the run, read the snapshot, and safely restored the file. |
| V2-005 | Low | `audit doctor` retention warning named v0.1.0. | Updated to v0.2.0. |
| V2-006 | Low | Full historical policy content is not retained. | Documented: fingerprint comparison is available; full historical policy diff is not fabricated. |
| V2-007 | Low | Static shadow detection cannot prove arbitrary regex containment. | Documented and limited to reliable identical-matcher overlap. |

All blocker/high findings must be resolved before tagging. No architecture or product feature expansion is included in this hardening branch.

## Compatibility gates

- CLI: existing `run`, `log`, `show`, `restore`, `verify`, `doctor`, `sync`, and `access-token` remain registered and tested.
- MCP: v0.1 tool names and fields remain; MCP v2 adds tools/fields without removing them.
- API: existing routes and response fields remain; v2 routes are additive and preserve viewer/operator/admin checks.
- Hash: schema-1 uses the exact v0.1 canonical payload; schema-2 is versioned separately. Optional Stage 10 metadata is absent when reading old JSON.
- Policy: `allowed`, `pending`, `rejected`, `approved`, `confirm`, and `blocked` normalize to canonical v0.2 decisions.
- Setup: preview by default; malformed configuration fails; apply performs merge, bounded backup, and atomic replacement.

## Security review

Reviewed RBAC, approval/rollback separation, workspace and symlink containment, redaction, simulation side effects, MCP context ownership, idempotency, payload bounds, YAML/RE2 limits, XSS/control-character rendering, and HTTPS sync. Test credential strings are explicit redaction fixtures, not secrets. Source and history scans, privacy scan, artifact scan, and final release scan are recorded in the Stage 11 report.
